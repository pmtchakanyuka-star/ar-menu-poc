# Scan the real plate, then automate everything after

For photoreal 3D models that match the plate, the October 2026 answer is **photogrammetry, not generative AI**. Shoot 60–120 cross-polarized turntable photos and reconstruct them with the **RealityScan CLI** (free under $1M revenue) or the fully open **COLMAP/GLOMAP → OpenMVS** stack on a rented Linux GPU. Then run a scripted **headless Blender** pass for cleanup, decimation and baking, compress with **gltf-transform**, and serve one GLB through **`<model-viewer>`**, which also produces the USDZ for iPhones. The earlier results looked bad because a few photos from one angle give a reconstruction tool almost nothing to triangulate, and they push a generative tool into inventing the back, sides and garnish. Fixing the capture will improve quality more than switching tools. Blender MCP is useful for writing and visually checking the Blender cleanup script, but it cannot reconstruct a dish. Higgsfield's 3D feature is single-image generation that produces a plausible dish rather than this dish, so it does not belong on the main path. Professional AR-menu vendors also scan rather than generate, and at £49 per dish for outsourced work, a 5–20 dish DIY pilot is cheap to justify. Two things are still unknown: no published benchmark covers any of these tools on plated food, and the per-dish GPU costs below are estimates.

## Why few photos from one angle failed, and what the tools actually do

Photogrammetry rebuilds surfaces by matching the same point across many overlapping views. Guides ask for **50–85% overlap**, **about 10–15° turntable steps** and **several camera heights** ([UCLA](https://dal.ucla.edu/seams/node/477); [Dartmouth](https://dreamstudio.dartmouth.edu/?p=630); [Oxford Brookes](https://telsupport.brookes.ac.uk/articles/how-do-i-create-a-3d-model-using-photogrammetry/)). A handful of shots from one height leaves the sides and undersides unseen, so you get holes, smeared texture and floating blobs. Food makes this harder. Glossy sauces and plate rims show highlights that move between views, and curved food cannot be angled to avoid glare the way a flat surface can ([Springer](https://link.springer.com/chapter/10.1007/978-3-031-35593-6_7)). Shiny, transparent and featureless surfaces are where photogrammetry is known to fail ([UNSW](https://www.making.unsw.edu.au/learn/photogrammetry/)).

**Higgsfield** is mainly a video and image platform. Its 3D feature turns an image into a GLB, and an August 2026 Blender add-on places generated geometry using Higgsfield's cloud ([WikiDocs](https://wikidocs.net/blog/@openwiki/29644/)). No public source names the underlying model. It most likely behaves like other single-image generators. Those models build coarse shape first and fill in fine detail last, struggle with thin continuous structures such as noodles and repeated textures such as seeds ([AI Weekly](https://aiweekly.co/alerts/why-ai-generated-food-images-look-so-wrong-per-researchers)), and in one food-image study left out items such as lemon wedges 15% of the time ([arXiv 2507.06571](https://arxiv.org/pdf/2507.06571)). That kind of output looks "AI polished" but is not faithful, which is the opposite of what this project wants, and it raises truth-in-menu questions.

**Blender MCP** (ahujasid/blender-mcp, now `mcp-for-blender`) connects an LLM to a live Blender session. Its core tool runs arbitrary Python. Other tools show the viewport, summarize the scene, import assets, and call the same AI generators (Tripo, Hunyuan3D, Rodin, Meshy) ([GitHub](https://github.com/ahujasid/blender-mcp)). It has no photogrammetry capability. Long requests time out, the socket has no authentication, and telemetry is on by default. Use it to develop and visually check a bpy cleanup script interactively, then run that script with `blender -b -P` so batches can be repeated without an LLM.

## Ranked pipeline for a 5–20 dish pilot

| Rank | Stage | Tool (license/cost) | Why |
|---|---|---|---|
| 1 | Capture | Dedicated camera, turntable, cross-polarized LEDs, RAW | Capture quality decides fidelity more than software choice |
| 2 | Masking | rembg/BiRefNet in batch, SAM 2 to fix failures | BiRefNet is strong on fine edges but fails when subject and background blend ([BRIA](https://bria.ai/introducing-the-rmbg-v2-0-model-the-next-generation-in-background-removal-from-images)) |
| 3a | Reconstruction (primary) | RealityScan 2.1+ CLI, Linux build under Wine | Free under $1M revenue ([license](https://www.realityscan.com/license)); documented CLI with an official Linux CLI build ([CG Channel](https://www.cgchannel.com/2025/11/epic-games-releases-realityscan-2-1/)) |
| 3b | Reconstruction (fully open) | COLMAP 4.x (GLOMAP built in) → OpenMVS | BSD-licensed SfM with global mapping and learned matching ([Radiance Fields](https://radiancefields.com/colmap-4.2.0-adds-multi-component-global-mapping-and-loma-learned-matching)); check OpenMVS's license (believed AGPL) |
| 4 | Cleanup/bake | Headless Blender bpy (authored via Blender MCP) | Remove floaters, decimate, unwrap, bake color/normal, put origin at plate base, set scale in meters |
| 5 | Optimize | gltf-transform: simplify, resize 2048, meshopt, webp/KTX2 | One-command pipeline ([gltf-transform](https://classic.yarnpkg.com/en/package/@gltf-transform/core)) |
| 6 | Deliver | `<model-viewer ar ar-modes="webxr scene-viewer quick-look">` behind an HTTPS page linked by QR code | Generates USDZ automatically since v1.7 ([Khronos](https://www.khronos.org/news/permalink/model-viewer-1.7-released-with-auto-generation-of-usdz-on-the-fly)) |

RealityScan ranks above the open stack because it produces cleaner textured meshes with less tuning and now has a supported CLI. One thing to check first: nobody has verified whether its EULA allows headless use on a cloud server. If that is a problem, COLMAP → OpenMVS is the drop-in replacement, and both can share the same SfM outputs. **Meshroom 2025.1** (MPL-2.0) is a strong third choice. It now ships dedicated object and turntable pipelines plus color calibration ([GitHub](https://github.com/alicevision/Meshroom/releases/tag/v2025.1.0)). **Apple Object Capture** accepts DSLR JPGs (20–200 images) and writes USDZ directly, but it needs a Mac and cannot recover real-world scale from DSLR photos ([Apple](https://developer.apple.com/documentation/realitykit/photogrammetrysession.md)).

Target the AR budgets. iOS Quick Look's rule of thumb is about **100k polygons and one set of 2048² textures**, and memory is the limit: a 1.6 MB USDZ with 4096² textures still failed ([Apple forums](https://developer.apple.com/forums/thread/693867)). Scene Viewer-style guides say **30–50k triangles and under 5–10 MB** ([Vyking](https://docs.vyking.io/docs/model-requirements); [Power.xyz](https://power.xyz/resources/support/doc/3d-asset-specs/)). A sensible target per dish is 20–60k triangles, one material, 2048 textures and a GLB of 2–5 MB. To keep dishes at true 1:1 size, Scene Viewer supports `resizable=false` ([Google](https://developers.google.com/ar/develop/java/scene-viewer)). It is unverified whether model-viewer's automatic USDZ survives Meshopt- or KTX2-compressed inputs, so keep an uncompressed or WebP variant for iOS until you have tested it.

## Alternatives and where each fits

**Gaussian splatting** handles gloss and thin garnish better than photogrammetry. An ISPRS study found fewer reflection artifacts with no loss of accuracy elsewhere ([ISPRS](https://isprs-archives.copernicus.org/articles/XLVIII-2-W8-2024/371/2024/)). The drawback is iPhones: Quick Look cannot display splats ([Apple forums](https://developer.apple.com/forums/thread/804604)), and KHR_gaussian_splatting was still a release candidate in mid-2026 ([Khronos](https://www.khronos.org/news/press/gltf-gaussian-splatting-press-release)). Splats are therefore an optional in-page hero view or Android AR feature (SuperSplat, Spark), trained with gsplat/nerfstudio from the same COLMAP poses. They are not the main deliverable. Mesh extraction from splats (PGSR, 2DGS, GOF) is improving but noisier on thin structures ([arXiv 2506.18575](https://arxiv.org/pdf/2506.18575)). The Inria-derived code is also non-commercial only ([ScanCode](https://scancode-licensedb.aboutcode.org/gaussian-splatting-2024.html)), so use it for evaluation only.

**Phone apps** are a quick sanity check. **KIRI Engine 4.0** gives free users unlimited GLB/USDZ exports and up to 150 photos per scan ([All3DP](https://all3dp.com/4/kiri-engines-free-4-0-update-gives-you-unlimited-photogrammetry-exports/)). Sources disagree on whether uploading DSLR photos on the web is free. Polycam's free tier exports only glTF ([Polycam](https://learn.poly.cam/hc/en-us/articles/27756102599572)). **Open image-to-3D models** are the right tool only for things that cannot be scanned, such as glassware and clear drinks, and those models should be labelled as representative. TRELLIS.2 (MIT, about 24 GB VRAM) is the commercially safe choice ([Webkul](https://webkul.com/blog/trellis-2/)). Hunyuan3D 2.1 is non-commercial ([HF](https://huggingface.co/tencent/Hunyuan3D-2.1/blob/38e83be15b2054c29a8ae2e2ef69daf68b7dd923/hy3dpaint/utils/multiview_utils.py)). The benchmark for a DIY pilot is **ARmenu at £49 per dish or £299 for 15** ([Petpooja](https://blog.petpooja.com/glossary/ar-menu/)).

## Capture checklist for each dish

| Item | Setting |
|---|---|
| Rig | Camera on a tripod, plate on a turntable over black velvet, with a scale ruler or coded targets outside the plate ([Pix-Pro](https://www.pix-pro.com/blog/cross-polarization)) |
| Light | 2–3 LED panels with polarizer film and a circular polarizer on the lens rotated to cancel highlights; otherwise very diffuse, even light ([Pix-Pro](https://www.pix-pro.com/blog/cross-polarization)) |
| Camera | Manual exposure, white balance and focus; RAW; f/8–f/11; low ISO (a reference capture used f/20, 1/60 s, ISO 400 ([Fab](https://www.fab.com/listings/1a1c0e81-3cd2-487c-8bc1-a743350392b8))) |
| Color | Gray card or color checker in the first frame |
| Coverage | 3 heights × 24–36 steps (10–15°), plus a near-overhead ring: 72–120 frames |
| Masking aid | One empty-turntable frame per height, or "exclude stationary tie points" ([Dartmouth](https://dreamstudio.dartmouth.edu/?p=630)) |
| Timing | Finish in minutes, before sauces dull or garnish wilts; let steam die down first (add it back later as an effect if wanted) |
| Problem areas | Glossy plate rims (replace with a modeled plate if needed); thin herbs (add back as alpha cards); glasses (model by hand or generate, labelled) |
| Record | Plate diameter in mm, for checking scale |

## Conclusion

The fidelity problem is mostly a capture problem, and it can be measured. Every stage after the shutter can be automated on Linux with free tools, so Claude can realistically take a folder of RAW files and return a GLB plus a model-viewer page with no manual steps. Blender MCP's real value is speed while developing that script, not running it in production. The open risks are specific: RealityScan's EULA terms for cloud use, OpenMVS licensing, how well model-viewer's USDZ output handles compressed GLBs, and actual GPU minutes per dish. A pilot answers all four.
